# Architecture

This repository publishes Dev Container features to `ghcr.io/nerdit-tech/devcontainer-features`. Each feature is a self-contained unit under `src/<feature>/` with its own version, changelog, and tests.

## Feature categories

The features fall into three categories:

### 1. CLI installers

Install a tool onto the system PATH. No volumes, no lifecycle hooks.

| Feature | Tool |
|---------|------|
| `opencode` | OpenCode CLI |
| `podman-remote` | Podman remote client |
| `xdg-utils` | xdg-utils with host browser pipe wrapper |

These features have a `test/<feature>/test.sh` that runs in a plain container (autogenerated test path).

### 2. Data persistence

Persist application data/config across container rebuilds via named volumes.

| Feature | Tool | Volumes |
|---------|------|---------|
| `claude-cache` | Claude Code | `claude-cache` |
| `opencode-data` | OpenCode | `opencode-data`, `opencode-config` |
| `go-cache` | Go | `go-build`, `go-pkg` |

These features declare named volumes in their manifest and use `onCreate.sh` to symlink the application's expected directories into the mount points. They have `test/<feature>/scenarios.json` + scenario scripts that exercise the real mount/onCreate flow.

### 3. Host integration

Bridge the container to the host machine via bind mounts.

| Feature | Host resource | Container mount |
|---------|---------------|-----------------|
| `podman-remote` | Podman socket | `/tmp/podman.sock` |
| `xdg-utils` | Browser pipe | `/tmp/hostbrowserpipe` |

These features do not declare the bind mount themselves (the path is machine-specific). The consuming `devcontainer.json` must declare the `mounts` entry.

## Lifecycle

```
Image build (root)
  └─ install.sh
       └─ Places files (e.g. onCreate.sh → /usr/local/share/<feature>/)

Container create (remote user)
  └─ onCreate.sh (via onCreateCommand)
       └─ chown mount points
       └─ Symlink app dirs → /mnt/<volume>
```

## Release pipeline

```
PR merged to main
  └─ release-please opens release PR (version bump + changelog)
       └─ Merge release PR
            └─ Tag pushed (<id>/v*)
                 └─ release.yml workflow
                      └─ devcontainers/action builds + publishes to GHCR
                      └─ Generates README.md for each feature
                      └─ Uploads feature archives as build artifacts
```

## Testing strategy

| Test path | What it covers | Features |
|-----------|---------------|----------|
| Autogenerated (`test.sh`) | CLI installed, binary on PATH | opencode, podman-remote, xdg-utils |
| Scenario (`scenarios.json` + scripts) | Volume mounts, onCreate symlinks | claude-cache, opencode-data, go-cache |

CI scopes tests to changed features. Changes outside `src/` and `test/` run the full matrix.
