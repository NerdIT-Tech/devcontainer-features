# Troubleshooting

Common issues and their solutions when consuming or developing NerdIT-Tech Dev Container Features.

## Feature consumption issues

### Volume not mounted

**Symptom:** `~/.claude`, `~/.local/share/opencode`, or Go cache directories are empty after container rebuild.

**Cause:** The feature's `onCreate.sh` symlinks the directory into the named volume. If the volume is not mounted (e.g. the feature was not included in `devcontainer.json`), the symlink target does not exist.

**Fix:** Ensure the feature is listed in your `devcontainer.json` `features` block. The volume is self-declared by the feature — no extra `mounts` entry is needed.

### Symlink conflicts

**Symptom:** `onCreate.sh` fails or the symlink points to the wrong location.

**Cause:** A pre-existing directory (not a symlink) exists at the target path (e.g. `~/.claude`). The script renames it to `<dir>-old` and creates the symlink, but if the rename fails (permissions, read-only filesystem), the symlink cannot be created.

**Fix:** Remove the conflicting directory manually and restart the container:

```sh
rm -rf ~/.claude-old   # or whichever directory is conflicting
```

Then rebuild the container.

### Permission errors on mount points

**Symptom:** `onCreate.sh` fails with "permission denied" when chowning or writing to `/mnt/<volume>`.

**Cause:** The named volume was created with different ownership, or the remote user does not have sudo access.

**Fix:** The `onCreate.sh` scripts use a `sudo()` helper that falls back to direct execution when running as root. If you are not root and do not have passwordless sudo, ensure your devcontainer user has sudo access (typically handled by `ghcr.io/devcontainers/features/common-utils`).

### Host socket / pipe not available (podman-remote, xdg-utils)

**Symptom:** `podman` commands fail with "connection refused" or `xdg-open` does not open the host browser.

**Cause:** The host bind mount is not declared in `devcontainer.json`. These features do not declare the mount themselves because the path is machine-specific.

**Fix:** Add a `mounts` entry to your `devcontainer.json`:

```jsonc
// For podman-remote
"mounts": [
  "source=/var/run/user/1000/podman/podman.sock,target=/tmp/podman.sock,type=bind"
]

// For xdg-utils
"mounts": [
  "source=/tmp/hostbrowserpipe,target=/tmp/hostbrowserpipe,type=bind"
]
```

## Development issues

### `mise run validate` fails

**Symptom:** JSON parse error or bash syntax error reported for a feature.

**Fix:** Validate the manifest and scripts locally:

```sh
python3 -c "import json; json.load(open('src/<feature>/devcontainer-feature.json'))"
bash -n src/<feature>/install.sh
bash -n src/<feature>/onCreate.sh   # if present
```

### `mise run test` fails

**Symptom:** The autogenerated test fails in CI or locally.

**Fix:** Run the test with verbose output:

```sh
mise run test -- <feature> mcr.microsoft.com/devcontainers/base:ubuntu
```

Check that `test/<feature>/test.sh` sources `dev-container-features-test-lib` and calls `reportResults`.

### `mise run test-scenarios` fails

**Symptom:** Scenario tests fail for volume/lifecycle features.

**Fix:** Ensure `test/<feature>/scenarios.json` is valid JSON and that the scenario script exists. The scenario test runs the feature with the declared mounts and runs the scenario script inside the container.

### Release-please PR not opened

**Symptom:** Merged PR to `main` does not trigger a release.

**Fix:** Ensure the commit message follows Conventional Commits. The `conventional-commits.yml` workflow enforces this. If the commit message is invalid, amend it and force-push.

### GHCR package is private

**Symptom:** `devcontainer` fails to pull the feature with a 401 error.

**Fix:** GHCR packages created under an org are private by default. The `release.yml` workflow checks for this and fails. To fix, go to the GitHub Packages web UI and set the package visibility to Public, then re-run the release workflow.
