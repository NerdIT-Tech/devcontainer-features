# AGENTS.md

Dev Container features for NerdIT-Tech, published to `ghcr.io/nerdit-tech/devcontainer-features/<id>:<major>`.

## Layout

- `src/<feature>/` — one feature per dir: `devcontainer-feature.json`, `install.sh`, `version.txt`, `CHANGELOG.md`. No shared files at `src/` root — duplicate per feature.
- `test/<feature>/` — either `test.sh` (standalone, autogenerated CI path) or `scenarios.json` + scripts (volume/lifecycle features). New scenarios must be wired into `.github/workflows/test-features.yml` matrix lists (`autogen_all` / `scenarios_all`).
- `docs/adrs/` — binding rules (R-FEAT-*, R-TEST-*, R-SHELL-*); read before editing `src/` or `test/`.
- `.release-please-config.json` — every feature dir must be registered here (release-type `simple`, version from `version.txt` + `devcontainer-feature.json`).

## Rules that differ from defaults

- All shell scripts: `#!/usr/bin/env bash` + `set -euo pipefail`.
- `install.sh` runs as root at build; it may only place files (e.g. copy `onCreate.sh` to `/usr/local/share/<feature>/`). Never touch remote-user home or volumes there.
- User-scoped setup (symlinks into volumes, XDG wiring) goes in `onCreate.sh`, referenced via `onCreateCommand` in the manifest.
- Conventional Commits required (CI enforces); versions/changelogs are release-please output — never edit `version.txt`/`CHANGELOG.md` by hand.
- Release is tag-triggered (`<id>/v*`) plus manual `workflow_dispatch` on `release.yml`.

## Verify locally

Tools and tasks are pinned via mise (`.mise.toml`): `mise install` once, then:

```sh
mise run validate                              # JSON + bash -n checks
mise run lint-yaml                             # yamllint
mise run lint-actions                          # actionlint
mise run test -- <feature> [baseImage]         # autogenerated path
mise run test-scenarios -- <feature>           # scenario features
```

Devcontainer CLI and other tool versions come from mise, not a global npm install. CI scoping: changing files outside `src/` and `test/` runs the whole matrix.

Repo-local OpenCode config: `.opencode/opencode.json` (ponytail plugin, agents, skills under `.opencode/`).
